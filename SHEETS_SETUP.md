# Google Sheets Storage Setup

PostgreSQL is no longer required by the bot runtime. Google Sheets stores runtime state, trades, orders, strategy decisions, learning checkpoints and candidate strategy suggestions.

## 1. Create the Sheet

Create a new blank Google Sheet, for example `BTC Bot Memory`.

Copy its spreadsheet ID from the URL. For a URL like:

```text
https://docs.google.com/spreadsheets/d/1AbCdEfG123456/edit
```

the ID is:

```text
1AbCdEfG123456
```

Open **Extensions -> Apps Script** and replace the editor content with `docs/google-sheets-backend.gs` from this repository.

## 2. Add Apps Script properties

In Apps Script open **Project Settings -> Script Properties** and add both values:

```text
BOT_SHEETS_SECRET=<long random secret, at least 32 characters>
BOT_SPREADSHEET_ID=<the spreadsheet ID copied above>
```

`BOT_SHEETS_SECRET` must match the Railway `GOOGLE_SHEETS_SECRET` value. `BOT_SPREADSHEET_ID` remains inside Apps Script and is not required as a Railway variable.

Do not commit either secret to GitHub.

## 3. Deploy as a Web App

In Apps Script:

1. Deploy -> New deployment
2. Type: Web app
3. Execute as: Me
4. Who has access: Anyone
5. Deploy
6. Copy the URL ending in `/exec`

The shared secret is required by every bot request. The Apps Script opens the exact spreadsheet configured with `BOT_SPREADSHEET_ID`, so it does not depend on an active spreadsheet context.

## 4. Railway variables

Set these on the bot service:

```text
GOOGLE_SHEETS_WEBAPP_URL=<the /exec URL>
GOOGLE_SHEETS_SECRET=<same value as BOT_SHEETS_SECRET>
SHEET_REQUIRED=true
```

`DATABASE_URL` is not required and can be removed from the bot service. A Railway PostgreSQL service is no longer required by the bot runtime.

## 5. Railway commands

```text
Pre-Deploy Command: npm run railway:predeploy
Start Command: npm start
Healthcheck Path: /ready
```

During predeploy `npm run storage:check` verifies that the Sheet backend is reachable.

## 6. Tabs

The Apps Script creates these tabs automatically on its first health request:

- `STATE` — restart recovery state (position, cooldown and runtime metadata)
- `TRADES` — closed trade memory
- `ORDERS` — order journal
- `DECISIONS` — every strategy decision / no-trade reason
- `CHECKPOINTS` — every 7 closed trades
- `CANDIDATES` — strategy improvement candidates generated by the learning engine

Trade and order history are deliberately kept outside the `STATE` JSON value so the state record does not grow into Google Sheets cell-size limits.

## 7. Learning behavior

- Every 7 closed trades: performance checkpoint.
- Every 21 closed trades: repeated-pattern confirmation.
- Candidate strategy changes are advisory only (`autoApply=false`).
- Risk and live trading settings are never self-modified from the Sheet.

## 8. Verify after deploy

Open:

```text
/ready
/api/runtime
/api/status
/api/learning
```

Expected `/ready` storage block:

```json
{
  "storage": {
    "mode": "google_sheets",
    "connected": true,
    "required": true,
    "error": null
  }
}
```
